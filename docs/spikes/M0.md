## 4. WASM web build with our plugins

**Tried.** `flutter build web --wasm` with every M0 plugin: firebase_core, firebase_auth, cloud_firestore, cloud_functions, firebase_analytics, firebase_crashlytics, firebase_remote_config, shared_preferences, package_info_plus, material_symbols_icons.

**Result.** It builds with no fallback to JavaScript, and the app runs in Chrome against the emulators: sign-in, the team switcher, and the tabs. CI builds it on every PR.

- Skwasm runs single-threaded unless the page is cross-origin isolated (`Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp`). Those headers can break Google and Apple sign-in popups, so we're **not** adding them yet. Revisit after spike 1, measuring scroll performance in chat (M3) single-threaded first.
- Icon fonts are tree-shaken (Material Symbols Rounded drops from 15 MB to about 90 KB).
- Plugins still to check when they arrive: `mobile_scanner` (QR, M2), image picking and compression (M3), `qr_flutter` (M2).

## 5. Security rules on the flat collections

**Tried.** `firestore.rules` with the helpers from ARCH §6.3, tested against the emulator in `functions/test/rules/firestore.test.ts`.

**Results.**

- **Membership checks from a query's `groupId` filter work.** A rule can call `exists()` on `groupMembers/{groupId}_{uid}` using `resource.data.groupId` from the query, so `messages.where('groupId','==',g).limit(50)` is allowed for members and denied for everyone else. Queries without the filter or without a `limit ≤ 100` are denied.
- **Cross-team isolation holds** for every collection tested: messages, groups, rosters, and RSVPs. Suspended teams lock out their members.
- **One RSVP per event and player works.** Two guardians answering for the same player write the same document; the last answer wins and `respondedBy` records who gave it. A parent who isn't the player's guardian, other teams, member RSVPs on youth events, and answers after the deadline (except by admins) are all rejected. The rule uses four lookups at most, as ARCH §10.2 budgets.
- **The message rate limit needed one more field.** As designed, the rule checked that the batch sets `lastPostedAt` to now and that the old value was a second old. But one batch can hold up to 500 writes, so a script could put many messages in one batch and each would pass. The fix: the batch also sets `groupMembers.lastPostedMessageId` to the new message's ID, and the message rule requires it to match. A batch can then create only one message. ARCH §6.2 and §6.3 are updated.
- **Rules paths need separate segments.** `get(/databases/$(database)/documents/$('groupMembers/' + id))` treats the whole string as one segment and fails. Paths must be written as `.../groupMembers/$(id)`.

**Left for later milestones.** Rules for polls (M5), events and series writes (M6), and documents (M7) arrive with those features, each with tests.

## 2. Links without Dynamic Links (done for Android and web)

**Done.**

- The dev web app is on Firebase Hosting at `https://battleplan-dev-ecce4.web.app`, which also serves `/.well-known/assetlinks.json` as `application/json` (from `web/.well-known/`). `firebase.json` no longer skips dot-folders when deploying.
- The Android manifest has an `autoVerify` intent filter for `/join/`, `/activate`, and `/g/` on a per-flavor host (`appLinkHost`: the dev Hosting domain for dev, `getbattleplan.app` for prod).
- On an Android 17 emulator, Android verified the domain (`pm get-app-links` → `verified`), and opening `https://battleplan-dev-ecce4.web.app/join/K7XPM2QR` launched the dev app straight onto the invite screen, with no browser and no chooser.
- `/join/<CODE>` is a route that works signed out. For now it shows the code; the team preview and Join button arrive in M2.

**Caveat.** `assetlinks.json` lists the SHA-256 of the debug key on Jared's Mac. Builds signed with another key (CI, another computer, the Play upload key) need their fingerprints added too (roadmap task 127).

**Email-link sign-in.**

- Turned on for the dev project (Email/Password with "email link" allowed), and built in: **Email me a sign-in link instead** on the email form, and an `/activate` screen that finishes sign-in (it asks for the address if this device didn't send the link).
- **Finding: `linkDomain` must be a custom domain.** Firebase rejects `web.app` and `firebaseapp.com` (`INVALID_HOSTING_LINK_DOMAIN`). Without `linkDomain`, links use the project's `firebaseapp.com` domain. So dev omits it, and prod will set `linkDomain: getbattleplan.app` once that domain is on prod's Hosting (task 116). Hosting serves `assetlinks.json` on both default domains, so the Android dev app verifies both, with a second intent filter for `/__/auth/links` on `authLinkHost`.
- **Android:** a generated sign-in link opened the dev app directly (no browser), and the app recognized it and asked for the email. The emulator was too slow to finish typing it.
- **Web:** the same kind of link opened `https://battleplan-dev-ecce4.web.app/activate`; entering the address signed in a new account and landed on the welcome screen. The test account was deleted afterwards.

**Left.** iOS Universal Links need the Apple membership (task 110).

## 3. Web push (Chrome passes)

**Built.** `PushRepository` (Firebase Cloud Messaging), `web/firebase-messaging-sw.js` for background delivery, and a dev-only **Settings → Push test** screen that asks permission and shows the device's token. It uses Firebase's default VAPID key; no project key was needed.

**Setup finding.** The dev project needed the **FCM Registration API** (`fcmregistrations.googleapis.com`) and the **FCM API** turned on before browsers could get tokens.
